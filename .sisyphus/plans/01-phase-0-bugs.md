## Bug #1: PKCE Verification is a No-Op

**File**: `app/controllers/shakha/auth_controller.rb:29` + `lib/shakha/pkce.rb:54-76`
**Severity**: 🔴 Fatal — PKCE doesn't actually verify the code_verifier

### Current broken code:
```ruby
# auth_controller.rb:29 — passes params[:code] as code_verifier
pkce_result = verify_pkce!(params[:code], params[:state])

# pkce.rb:71-75 — computes SHA256 of the auth code, compares against nothing
computed = PKCEMixin.generate_code_challenge(code_verifier)
code_challenge = params[:code_challenge]  # Google never sends this
if code_challenge.present?
  raise PKCEError, "Invalid code verifier" unless computed == code_challenge
end
```

### What's actually happening:
- `params[:code]` is the Google authorization code, not the PKCE code_verifier
- `params[:code_challenge]` is nil — Google doesn't echo the challenge in the callback
- The `if code_challenge.present?` guard always skips the check
- Only `state` parameter is verified (CSRF protection only, not PKCE)

### The fix:
```ruby
# In auth_controller.rb callback action:
def callback
  pkce_result = verify_pkce!(params[:state])
  exchange_code_for_tokens(params[:code], pkce_result[:verifier], pkce_result[:return_to])
rescue PKCEError, GoogleOAuthError => e
  # ... error handling unchanged
end

# In pkce.rb:
def verify_pkce!(state_param)
  pkce_json = cookies[PKCE_COOKIE_NAME]
  raise PKCEError, "No PKCE session found" unless pkce_json

  pkce_data = JSON.parse(pkce_json).with_indifferent_access
  raise PKCEError, "No PKCE session found" unless pkce_data

  stored_state = pkce_data[:state]
  stored_verifier = pkce_data[:verifier]
  stored_return_to = pkce_data[:return_to]

  cookies.delete(PKCE_COOKIE_NAME)

  raise PKCEError, "State mismatch" unless ActiveSupport::SecurityUtils.secure_compare(stored_state, state_param)

  { verifier: stored_verifier, return_to: stored_return_to }
end
```

### Key changes:
1. `verify_pkce!` takes only `state_param`, not a misnamed `code_verifier`
2. Returns the stored `verifier` for use in the Google token exchange
3. Uses `secure_compare` for state comparison (timing-safe)
4. The actual PKCE verification happens when Google validates the code_verifier against the code_challenge at the token endpoint — that's Google's job, not ours

## Bug #2: `public_materia` Typo → NameError

**File**: `lib/shakha/jwt_handler.rb:92`
**Severity**: 🔴 Fatal — crashes in standalone service mode with separate verification key

```ruby
# Line 92 — typo
return nil unless public_materia  # NameError: undefined local variable or method

# Should be:
return nil unless public_material
```

### The fix:
```ruby
def verification_key
  return signing_key&.public_key if signing_key

  public_material = Shakha.config.verification_key
  return nil unless public_material

  if public_material.start_with?("-----BEGIN")
    OpenSSL::PKey::EC.new(public_material)
  else
    OpenSSL::PKey::EC.new(Base64.decode64(public_material))
  end
end
```

**Note**: This module gets deleted in Phase 2 (JwtHandler is service infrastructure). Fix now to prevent crashes, delete later.

## Bug #3: Session Model Receives Non-Existent Columns

**File**: `app/controllers/shakha/auth_controller.rb:178-184`
**Severity**: 🔴 Fatal — `ActiveModel::UnknownAttributeError` on every sign-in

```ruby
# Current code passes ip_address and user_agent
Shakha::Session.create!(
  user: user,
  client: client,
  jti: SecureRandom.uuid,
  ip_address: request.remote_ip,   # ❌ No such column
  user_agent: request.user_agent    # ❌ No such column
)
```

### The migration schema (from README):
```ruby
create_table :shakha_sessions do |t|
  t.references :user, foreign_key: { to_table: :shakha_users }
  t.references :client, null: false, foreign_key: { to_table: :shakha_clients }
  t.string :token, null: false
  t.string :jti, null: false
  t.timestamps
end
```

### The fix — Option A: Add columns to migration:
Add `ip_address` and `user_agent` to the session migration. These are useful for session management.

### The fix — Option B: Remove from create call:
```ruby
Shakha::Session.create!(
  user: user,
  client: client
)
# token and jti are generated by before_create callbacks
```

### Decision: Add the columns. Session audit data is useful and the UI already references `session.ip_address`.

## Bug #4: Code Verifier Character Set Violates RFC 7636

**File**: `lib/shakha/pkce.rb:16-19`
**Severity**: 🟠 High — May cause Google token endpoint to reject the code_verifier

```ruby
def generate_code_verifier
  SecureRandom.urlsafe_base64(CODE_VERIFIER_LENGTH)
    .tr("-_", "+/")    # ❌ "+/" are NOT in the allowed charset
    .slice(0, CODE_VERIFIER_LENGTH)
end
```

### RFC 7636 allowed characters:
```
ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789-._~
```

`+/` are NOT in the allowed set. Google may reject verifiers containing these characters.

### The fix:
```ruby
def generate_code_verifier
  SecureRandom.urlsafe_base64(CODE_VERIFIER_LENGTH)
    .tr("-_", "")      # Remove non-allowed chars, keep only alphanumeric
    .slice(0, CODE_VERIFIER_LENGTH)
end
```

Wait — `urlsafe_base64` produces `[A-Za-z0-9_-]`. The RFC allows `-._~`. So we should KEEP `-` and `_`, not replace them. The fix is simply:

```ruby
def generate_code_verifier
  SecureRandom.urlsafe_base64(CODE_VERIFIER_LENGTH, padding: false)
end
```

Remove the `.tr` and `.slice` entirely. `SecureRandom.urlsafe_base64(64, padding: false)` produces ~86 characters, all in the allowed set. The RFC minimum is 43, maximum is 128. 86 chars is fine.

## Bug #5: Rate Limiter TOCTOU Race Condition

**File**: `lib/shakha/rate_limiter.rb:27-36`
**Severity**: 🟡 Medium — Two parallel requests can both pass the rate limit

```ruby
def check_rate_limit(key, max:, period:)
  return unless Shakha.config.rate_limiting_enabled

  cache_key = "shakha-rate:#{key}:#{request.remote_ip}"
  count = Rails.cache.read(cache_key).to_i + 1

  if count == 1
    Rails.cache.write(cache_key, count, expires_in: period.seconds)
  elsif count > max
    render json: { error: "Too many requests. Try again later." }, status: :too_many_requests
    return
  else
    Rails.cache.write(cache_key, count, expires_in: period.seconds)
  end
end
```

### Time-of-check-to-time-of-use race:
```
Request A: reads 0, writes 1  ✓ passes
Request B: reads 0, writes 1  ✓ passes (should have seen 1)
```

Both pass because they read before either wrote.

### The fix:
Use `Rails.cache.increment` which is atomic in most cache backends:

```ruby
def check_rate_limit(key, max:, period:)
  return unless Shakha.config.rate_limiting_enabled

  cache_key = "shakha-rate:#{key}:#{request.remote_ip}"
  count = Rails.cache.increment(cache_key, 1, expires_in: period.seconds)

  if count > max
    render json: { error: "Too many requests. Try again later." }, status: :too_many_requests
  end
end
```

Rails 7.1+ supports `Rails.cache.increment` with `expires_in`. For older versions, use `Rails.cache.write(cache_key, 1, expires_in: period.seconds, raw: true, unless_exist: true)` then `Rails.cache.increment(cache_key)`.

## Bug #6: `http_post` Has No Timeout or Error Handling

**File**: `app/controllers/shakha/auth_controller.rb:226-236`
**Severity**: 🟠 High — Network failures bubble up as 500 errors

```ruby
def http_post(url, body)
  uri = URI.parse(url)
  http = Net::HTTP.new(uri.host, uri.port)
  http.use_ssl = uri.scheme == "https"

  request = Net::HTTP::Post.new(uri.request_uri)
  request["Content-Type"] = "application/x-www-form-urlencoded"
  request.body = URI.encode_www_form(body)

  http.request(request)
end
```

### Missing:
- `http.open_timeout` — DNS/TCP handshake timeout (default: 60s, too long)
- `http.read_timeout` — Response read timeout (default: 60s, too long)
- No error handling for `Errno::ECONNREFUSED`, `SocketError`, `Net::OpenTimeout`, `Net::ReadTimeout`
- No HTTP status code checking — Google may return 400/401/429 with error JSON

### The fix:
```ruby
def http_post(url, body)
  uri = URI.parse(url)
  http = Net::HTTP.new(uri.host, uri.port)
  http.use_ssl = uri.scheme == "https"
  http.open_timeout = 5
  http.read_timeout = 10

  request = Net::HTTP::Post.new(uri.request_uri)
  request["Content-Type"] = "application/x-www-form-urlencoded"
  request.body = URI.encode_www_form(body)

  response = http.request(request)

  unless response.is_a?(Net::HTTPSuccess)
    Rails.logger.error("[Shakha] Google API error: #{response.code} — #{response.body.truncate(500)}")
    raise GoogleOAuthError, "Google returned #{response.code}"
  end

  response
rescue Net::OpenTimeout, Net::ReadTimeout, Errno::ECONNREFUSED, SocketError => e
  Rails.logger.error("[Shakha] Network error contacting Google: #{e.message}")
  raise GoogleOAuthError, "Unable to reach Google authentication service"
end
```
